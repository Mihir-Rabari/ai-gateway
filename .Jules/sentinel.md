## 2026-10-31 - Timing Attack Vulnerability in Secret Comparison
**Vulnerability:** The internal service secret in `apps/auth-service/src/routes/codexRoutes.ts` was being compared using a simple string equality check (`clientSecret !== internalSecret`). This is vulnerable to timing attacks where an attacker could theoretically guess the secret character by character by measuring the response time.
**Learning:** Comparing sensitive secrets, tokens, or passwords using standard equality operators (`===` or `!==`) exposes the application to timing attacks. While `apps/auth-service/src/routes/internalRoutes.ts` and other places used `crypto.timingSafeEqual`, this specific route missed the secure implementation. Node.js `crypto.timingSafeEqual` requires the inputs to be cast to `Buffer` and checked for equal length prior to the comparison.
**Prevention:** Always use `crypto.timingSafeEqual()` rather than simple equality operators for comparing sensitive internal tokens, client secrets, or passwords. Ensure both inputs are cast to `Buffer` and checked for equal length prior to the comparison to prevent timing attacks and `RangeError` exceptions if lengths differ.
